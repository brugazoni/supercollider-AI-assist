# Rebuilding SuperCollider IDE (Custom Auto-Execute Build)

This guide provides step-by-step instructions on how to rebuild the custom SuperCollider IDE on Windows to enable the **Auto-Execute** (auto-evaluate on file reload) feature.

## Prerequisites

Since you are rebuilding the C++ source code for the IDE, you need the standard SuperCollider build dependencies for Windows:

1. **Git**: To clone/manage the repository.
2. **CMake (3.5 or higher)**: The build system generator.
3. **Visual Studio C++ Build Tools**: Typically installed via Visual Studio (2019 or 2022) with the "Desktop development with C++" workload.
4. **Qt 5 (5.15 recommended)**: The UI framework used by SuperCollider.
5. **Python 3**: Sometimes required by SC's build scripts.
6. **Jack (Optional but recommended for audio routing)**

## Step 1: Prepare the Source Code

Ensure you have your modified `supercollider-AI-assist` repository ready. The critical files that were changed for this feature are:
- `editors/sc-ide/core/doc_manager.hpp`
- `editors/sc-ide/core/doc_manager.cpp`

Open your terminal (PowerShell or Command Prompt) and navigate to the root of the SuperCollider repository:

```powershell
cd C:\Users\Bruno Gazoni\Desktop\supercollider-project\supercollider-AI-assist
```

## Step 2: Configure the Build with CMake

> [!TIP]
> **Already have a `build` directory?**
> If you've compiled SuperCollider on this machine before and the `build` directory already exists with a valid CMake configuration, **you can skip Step 2 entirely and go straight to Step 3**. CMake and the build system (MSBuild/Ninja) are smart enough to detect that `doc_manager.cpp` changed and will only recompile what is necessary.

Create a build directory (if it doesn't exist) and run CMake to configure the project. Make sure you point CMake to your Qt installation.

```powershell
# Create a build directory
mkdir build
cd build

# Run CMake configuration (replace the Qt path with your actual Qt MSVC installation path)
cmake -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH="C:\Qt\5.15.2\msvc2019_64" ..
```
*Note: Adjust the Generator (`-G`) depending on your Visual Studio version. Adjust the Qt path to match where Qt5 is installed on your system.*

## Step 3: Compile the IDE

Once CMake configures successfully, you can compile the project using the following command. The `--config Release` flag ensures an optimized build.

```powershell
cmake --build . --config Release --target SuperCollider
```

*Note: Compiling just the `SuperCollider` target is faster if you only modified the IDE codebase (it skips rebuilding the server/language). If you want to rebuild absolutely everything, you can simply run `cmake --build . --config Release` without `--target`.*

## Step 4: Locate the Executable

After the build completes successfully, the new custom `scide.exe` will be located in the build directory, typically under:

```
build\Release\scide.exe
```
or 
```
build\editors\sc-ide\Release\scide.exe
```

## Step 5: Update the SC-Gen-RAG Configuration

Once rebuilt, you should test the IDE by opening it. 
To use the auto-execute feature with the Python script:
1. Make sure `config.py` in your SC-Gen-RAG project points to the correct, newly built `sclang` (for validation) if its path changed.
2. In the SC IDE, open the **Language** menu. At the bottom, you will see a checkable option called **Auto-Evaluate Externally Modified Files**. This is ON by default.
3. When this is checked, any `.scd` file that is reloaded externally (which the Python script triggers) will automatically evaluate its last `(...)` block. You can disable this at any time by unchecking it from the menu.

## Troubleshooting

- **Missing Qt Modules:** If CMake complains about missing Qt modules (like WebSockets or WebEngine), ensure you installed the full Qt 5 suite via the Qt Maintenance Tool.
- **File not evaluating:** Verify that the code block generated by the LLM is wrapped in explicit top-level parentheses `( )`, as the custom backward-scan algorithm relies on finding this structure at the start of a line.
- **The procedure entry point ... could not be located:** This is a classic Windows "DLL Hell" error. It means `scide.exe` (or its child process `sclang.exe`) is finding a different, older version of Qt's DLLs (e.g., `Qt5Network.dll` or `Qt6PrintSupport.dll`) somewhere in your system `PATH` instead of the ones it was just compiled against.  
  **Fix it using `windeployqt`:** Open your Qt command prompt (or use the full path to `windeployqt.exe` in your Qt `bin` folder) and run it on **BOTH** executables to copy the correct DLLs right next to them:
  ```powershell
  # Deploy to the IDE
  C:\Qt\5.15.2\msvc2019_64\bin\windeployqt.exe "C:\Users\Bruno Gazoni\Desktop\supercollider-project\supercollider-AI-assist\build\editors\sc-ide\Release\scide.exe"
  
  # Deploy to the language interpreter (sclang)
  C:\Qt\5.15.2\msvc2019_64\bin\windeployqt.exe "C:\Users\Bruno Gazoni\Desktop\supercollider-project\supercollider-AI-assist\build\lang\Release\sclang.exe"
  ```
  *(Make sure to adjust the Qt path to match your actual installation folder).*
