# SC-Gen-RAG Validation Pipeline: Multi-Tiered Syntax Checking and Auto-Correction

This document outlines the architectural implementation of the `SC-Gen-RAG` code validation pipeline. Because Large Language Models (LLMs) are prone to generating syntactically incorrect code—particularly in domain-specific languages like SuperCollider (sclang)—a robust, multi-tiered validation approach is required before executing code on the audio server.

The pipeline comprises three core components:
1. **Tier 1 (Structural Validation)**: Fast, heuristic checks in Python.
2. **Tier 2 (Subprocess Validation)**: True syntax parsing via a headless `sclang` process.
3. **LLM Auto-Correction**: A cyclical feedback loop where errors are fed back to the LLM for resolution.

---

## 1. Tier 1: Structural Validation (Python Heuristics)

The first line of defense is implemented purely in Python (`_tier1_structural_check` in `agent_graph_incremental.py`). This tier avoids invoking external binaries and acts as a fast-fail filter for obvious hallucinations or structural deformities.

### Implementation Details:
*   **Bracket Matching**: The script scans the incoming block to ensure all opened parentheses `()`, brackets `[]`, and braces `{}` are correctly closed. SuperCollider code heavily relies on deeply nested functional blocks, and a missing brace is the most common LLM failure mode.
*   **Empty Block Detection**: The check ensures the LLM did not just generate an empty `(...)` wrapper or comments, forcing it to generate actual DSP or language instructions.

If Tier 1 fails, the error (e.g., *"Unmatched opening '{' found"* ) is immediately passed to the LLM Auto-Correction node, bypassing the slower Tier 2 evaluation step entirely.

---

## 2. Tier 2: Subprocess Validation (Headless Sclang)

Because SuperCollider is a highly dynamic Smalltalk-derived language, Python regular expressions and structural checks cannot definitively prove that a code block is valid sclang code. Real syntax validation requires the actual SuperCollider interpreter. 

### Implementation: The `SclangValidator` module
We created `sclang_validator.py` to manage a long-running, headless `sclang` subprocess managed via standard I/O (stdin/stdout).

**The Execution Wrapper:**
To separate true syntax/parse errors from legitimate runtime errors (e.g., calling an undefined variable or `Ndef` before it exists in the execution graph), the Python agent wraps the incoming block in an exception-handling compile string before sending it to the subprocess:

```supercollider
try { 
    { 
        // ... INCOMING GENERATED CODE ...
    }.value; 
    
    // If it compiles and evaluates without syntax errors, print success
    "\n__SCLANG_VALID__\n".postln; 
} { |err| 
    // If it throws, check if it's a compile error or just a runtime error
    if(err.isKindOf(Exception)) {
        // We ignore pure runtime errors for validation purposes
        "\n__SCLANG_VALID__\n".postln;
    } {
        // True parse/syntax mapping error
        ("\n__SCLANG_ERROR__: " ++ err.errorString).postln;
    }
};
```

**State Mirroring:**
Crucially, when a block *passes* validation and is officially accepted into the composition, the `SclangValidator` performs a `mirror_block()` operation. It silently evaluates the actual code natively so its internal environment (dictionary of `~variables`, `Ndef`s, and `SynthDef`s) remains synchronized with the main SC-IDE environment. This ensures subsequent validations don't fail due to missing context.

---

## 3. LLM Validation & Auto-Correction (The Feedback Loop)

When either Tier 1 or Tier 2 detects a failure, the pipeline routes the execution flow via LangGraph to the `syntax_correction_node`. 

### The Correction Mechanism:
The pipeline takes the exact error output generated by the validation tiers (e.g., the stack trace from `sclang`) and packages it into a strict prompt:
> *"The SuperCollider code you just generated contains syntax errors. Here is the code you generated: [...] Here is the error output: [...]. Please analyze the error and return ONLY the corrected code block."*

### Stateful Retry Bounding (`MAX_SYNTAX_RETRIES`):
To prevent the agent from getting stuck in an infinite loop of trying to fix unfixable hallucinations, the `IncrementalState` maintains a `syntax_check_attempts` counter. 
*   If the LLM corrects the code successfully, the graph loops back to the Validation Nodes.
*   If the graph reaches `config.MAX_SYNTAX_RETRIES` (typically 3), it forces an abort of the block. If `auto-execute` is off, it traps to human intervention; if on, it either discards the block or gracefully downgrades.

---

## Conclusion

This multi-tiered architecture ensures absolute syntactical safety before injecting code into the live SuperCollider environment. By layering fast Python heuristics (Tier 1) over a robust native exception-handling compiler subprocess (Tier 2), and wiring both into a cyclical LLM-correction loop, `SC-Gen-RAG` bridges the gap between probabilistic generative code and deterministic audio server execution.
